# 授权校验清单（licensing）

本目录存放「快递取件码」**已购订单白名单**，供快捷指令联网校验购买状态。

> ⚠️ 本目录是**运营数据**，不属于面向用户的说明文档；不要在根 README 中主动宣传其位置。

## 一、目录内容

| 文件 | 作用 |
| --- | --- |
| `orders.json` | 白名单数据本体，快捷指令读取的唯一数据源 |
| `add-order.py` | 本地维护脚本（追加 / 列表 / 删除 / 试算 / 切换匹配口径） |
| `README.md` | 本文件：数据结构约定 + 快捷指令读取方案 + 安全边界 |

## 二、数据源地址（快捷指令读取用）

```
https://gitee.com/zhang_wangning/shortcut_pickup_code/raw/master/licensing/orders.json
```

> 该地址匿名可访问，无需 Token。更新后 Gitee raw 可能有数分钟缓存延迟。

## 三、数据结构（**字段名是快捷指令硬编码依赖，不得随意变更**）

```json
{
  "schemaVersion": 1,
  "product": "快递取件码",
  "productVersion": "V7.3.0",
  "purchaseChannel": "小红书 · 极客ZHANG",
  "matchMode": "exact",
  "suffixLength": 0,
  "updatedAt": "2026-09-20",
  "count": 2,
  "orders": [
    {
      "orderId": "2026092012345678901",
      "activatedAt": "2026-09-20",
      "note": "小红书首单"
    },
    {
      "orderId": "9876543210987654321",
      "activatedAt": "2026-09-20",
      "note": ""
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schemaVersion` | 数字 | 结构版本。日后若大幅调整结构则递增，快捷指令可据此兼容旧版 |
| `product` / `productVersion` | 字符串 | 商品标识与适用版本，便于同一仓库承载多个商品时区分 |
| `purchaseChannel` | 字符串 | 购买渠道 |
| `matchMode` | 字符串 | 匹配口径：`exact` = 全号比对；`suffix` = 仅比对末 `suffixLength` 位 |
| `suffixLength` | 数字 | `matchMode=suffix` 时生效的尾号位数；`exact` 时为 `0` |
| `updatedAt` | 字符串 | 最后更新时间 `YYYY-MM-DD` |
| `count` | 数字 | 白名单条数（应与 `orders` 长度一致，用于校验文件完整性） |
| `orders` | 数组 | 已购订单列表，**最新添加的排在最前** |
| `orders[].orderId` | 字符串 | 订单号（或按 `matchMode` 存储的尾号），**比对主键** |
| `orders[].activatedAt` | 字符串 | 登记日期 `YYYY-MM-DD` |
| `orders[].note` | 字符串 | 备注，可为空 |

## 四、维护方式

一律走脚本，避免手工编辑破坏 JSON 格式或漏改 `count`：

```bash
# 追加一笔订单（自动去重、更新 count 与 updatedAt）
python3 licensing/add-order.py add 2026092012345678901 --note "小红书首单"

# 查看白名单
python3 licensing/add-order.py list

# 删除一笔订单
python3 licensing/add-order.py remove 2026092012345678901

# 本地模拟快捷指令校验（不联网，用于自测）
python3 licensing/add-order.py check 2026092012345678901
```

**追加后必须 `commit + push`**，快捷指令才能读到；raw 有缓存延迟，可稍等数分钟或强刷。

## 五、快捷指令侧读取方案（后期实现依据）

目标：让快捷指令判断「当前设备是否已购买」。

### 5.1 动作链（exact 模式）

| 步 | 动作 | 配置 |
| --- | --- | --- |
| 1 | **获取 URL 内容** | GET `licensing/orders.json` 的 raw 直链，方法 `GET` |
| 2 | **从输入获取字典** | 输入 = 上一步结果（把 JSON 文本解析为字典） |
| 3 | **从字典获取值** | 键 `matchMode`，取出匹配口径 |
| 4 | **从字典获取值** | 键 `orders`，取出订单数组 |
| 5 | **重复（遍历）** | 遍历上一步的数组，每轮当前项为一条订单字典 |
| 6 | **从字典获取值** | 键 `orderId`，取出该条订单的比对值 |
| 7 | **如果** | `orderId` **等于**「用户输入的订单号」→ 判定**已购买**（置标志位并「退出重复」） |
| 8 | 循环结束仍未命中 | 判定**未购买** |

### 5.2 关键注意点

- **必须「退出重复」**：命中后立即跳出循环，否则后续轮次会继续执行、把标志位覆盖回未购买。
- **输入规范化**：用户常带空格或大小写差异，比对前先用「替换文本」去掉空格（若订单号为纯数字则只需去空格）。
- **网络异常兜底**：拉取失败（无网 / 接口异常）时**不应**直接判未购买，建议给「校验失败，请检查网络后重试」的独立提示，避免正版买家被误伤。
- **`matchMode` 分支**：若为 `suffix`，需先对用户输入取末 `suffixLength` 位再比对（用「匹配文本」正则 `\d{N}$` 提取，或「从输入获取文本」+ 长度处理）。
- **空数组安全性**：`orders` 为空数组时遍历 0 次，直接落到「未购买」分支，逻辑无需特殊处理。

## 六、⚠️ 安全边界（务必知悉）

**该机制是「使用门槛」，不是「防盗版」。** 原因有三：

1. **数据源公开可读**：Gitee raw 链接匿名可访问，任何人拿到仓库地址即可看到订单号列表。
2. **纯客户端校验**：判定逻辑全在快捷指令本体内，且本体可被查看、可被复制修改。
3. **「知道」即「通过」**：校验只验证「输入值与列表命中」，不验证输入值的来源，因此看到列表中任意一个订单号即可通过。

**真正起作用的屏障是「安装包不公开分发」**（仓库与公众号均不提供 V7.3.0 的安装入口）。白名单的价值在于：

- 让被转发的安装包在他人设备上显示「未购买」，形成心理门槛；
- 给正版买家一个明确的授权确认反馈；
- 集中登记订单，便于日后核对与追溯。

### 降低隐私暴露的替代口径：`suffix` 模式

全号存明文会把买家完整订单号公开在互联网上（订单号可能含购买时间等信息）。若不希望暴露全号：

```bash
python3 licensing/add-order.py mode suffix --length 10
```

切换后：

- 列表中只存订单号**末 10 位**（订单号前段通常含日期/店铺信息，尾段为随机流水，敏感度更低）；
- 快捷指令侧对用户输入同样取末 10 位后比对，**用户体感完全一致**（仍输入完整订单号）；
- 代价：`mode` 切换后**已有记录不会自动转换**（尾号无法反推全号），需清空重建。

> 📌 **建议**：`matchMode` 一经确定就不要再切换；如确需切换，先 `list` 备份，再清空重建。
