# 快递取件码 V7.1.3 优化说明

> 基于 Mac 本机 `Shortcuts.sqlite` 解析（Z_PK=420，最后编辑 2026-08-12 21:56），结合作者迭代说明整理。

## 基本信息

- **本体**：快递取件码 V7.1.3（Z_PK = 420）
- **动作规模**：150 个（V7.1.0 为 115 个，净增 35 个）
- **解析方式**：读 `~/Library/Shortcuts/Shortcuts.sqlite` 的 `ZSHORTCUTACTIONS.ZDATA`（整条指令序列的 bplist）。`.shortcut` 为 AEA1 签名包裹（magic `41454131`），不可逆向，故以 sqlite 本体为准。

## 六大优化（已逐项核验）

### 1. 版本更新检查：关闭后仍提示，不中断运行
- 配置字典新增「更新检查」项（True 开启 / False 关闭）。
- **关键变更**：此前关闭更新检查即完全跳过联网；现改为——关闭后仍会以**通知**方式推送新版本提示（通知标题「【快递取件码】版本更新通知，请立即更新」），但**不再 Exit 退出指令**，取件流程照常运行，不影响当前版本使用。
- 验证：动作流含 `If → Show Notification` 通知分支；「最新版本号」变量与通知文案已落地。

### 2. 取件码匹配规则精细化
- **新增「尾号」匹配**：正则 `(?<=尾号为?)\s*…(?=快件)` 捕获类似"尾号为 1234"的快件尾号。
- **新增「特殊格式取件码」匹配**：覆盖 `4、4、3486`、`3486` 等不规则取件码。用户样例「【浙江绿驿生活】快递码4、4、3486，您的申通快递已到智慧城80墅大厅快递驿站，请及时领取。」已内置为测试数据。
- **连接符统一**：所有取件码分隔符规范为 `-`（如 `4、4、3486` → `4-4-3486`），由多处 `Text Replace` 动作实现。
- 运单号正则同步增强，支持 `[A-Z]{0,3}\d{11,}` 等格式。

### 3. 显示格式可选
- 配置字典新增「显示格式」（True / False），控制三要素（快递平台 / 取件码 / 取件地址）的排列：
  - **True**：`【快递平台】取件码` + 换行 + `取件地址`
  - **False**：`取件码【快递平台】` + 换行 + `取件地址`
- 后续通过 `Text Match` + `If` + `Text Combine` 多分支按所选格式拼装。

### 4. 短信匹配机制重构
- **旧逻辑**：短信中必须存在快递公司名列表（快递｜兔喜生活｜顺丰｜圆通…）才继续，否则 Exit。
- **新逻辑**：改为检测**四个参数**——取件码、运单号、尾号、特殊格式取件码。四个参数**全部不存在**时才 Exit 停止运行。
- 验证：动作 63–66 为四个 `Text Match`，动作 67 `If` + 68 `Exit` 构成"全无则退出"判定。

### 5. 快递平台变量匹配放宽
- 保留正则 `(?:【)\w+】` 提取【】内平台名。
- **关键变更**：不再强制要求短信同时含「【」「】」。无平台名时统一兜底为 `【未知包裹】`（已验证兜底变量存在）。
- 解决"您有包裹已到达天誉店，取件码为 T5-4-1368…兔喜生活"类无【】短信的识别问题。

### 6. 导入时自动创建列表（可关）
- 配置字典新增「自动创建列表」（True / False）。默认 True：快捷指令首次运行自动在提醒事项创建「待取件📦」列表。
- 不需要自动创建时，改为 False 即可（动作含 `Reminders TTRCreate List App Intent`）。
